# Editorial focus

This file steers `--mode propose`. Edit it freely — it's the source of truth for
what kind of articles get proposed. Keep it concrete.

## Audience

Developers and self-taught builders who are learning by doing. People who write code
(or want to) and are teaching themselves modern AI/agent tooling. NOT school or
university students; NOT generic "study skills" readers.

## Topic areas (propose across these, spread the batch)

- **Agentic AI / building agents** — what an agent actually is, the control loop,
  tool design, memory, multi-agent tradeoffs, common failure modes.
- **Using & building with Claude Code** — first-week workflows, CLAUDE.md conventions,
  subagents, slash commands, MCP, getting consistent output.
- **Learning Python to build** — the subset that matters for AI/agent work
  (async, typing, dataclasses, context managers), not exam prep.
- **Learning JavaScript for AI apps** — just-enough JS to ship a frontend on an AI
  backend; runtime/browser confusion.
- **Learning to build, generally** — how to actually learn a new framework/tool by
  building with an AI assistant instead of reading docs front-to-back.

## Segment anchoring (required)

Every proposal must name a specific learner segment and speak to a concrete moment
(e.g. "developer debugging their first agent loop", "Python dev who freezes on async
when it matters"). No generic "developers who want to learn AI" framing.

## Tone

Practical, opinionated, honest about tradeoffs. Written by someone who has actually
built the thing. No hype, no listicles, no "in today's fast-paced world".

## Hard exclusions

- No school/university/exam-cram audiences.
- No generic study-tool content (Anki/Duolingo/Notion-as-study-app) — that's the old
  direction we're moving away from.
- Don't reproduce an article that already exists (see EXISTING COVERAGE passed at
  runtime), even reworded or with the brand name swapped for the generic category.
